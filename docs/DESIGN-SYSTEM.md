# Дизайн-система обоих пространств — инварианты (редизайн-2)

Полный список инвариантов дизайн-системы трекера и обучения (макеты Claude Design в `redesign/`, вне git). Вынесен из CLAUDE.md 2026-08-21 по размерному предохранителю; в CLAUDE.md остаётся краткий дайджест. Читать при любой правке UI-компонентов, экранов трекера/learn, карточки задачи, сайдбара.

Спека Claude Design в `redesign/` (вне git и вне rsync-деплоя). Что нельзя нарушать:

- **Цвет несёт смысл:** зелёный = «сделано/верно», амбер = акцент и текущее, красный = просрочка и ошибка, `--blue-deep` = карьерное/нейтрально-информативное. Кнопка создания — амбер, НЕ красный.
- **Ниже 12px в продуктовом UI не набирается ничего** (исключение — подпись таб-бара 11px). `--text3` в трекере не носит функционального смысла, только `--text2`.
- **Силуэт бейджа один:** 22px, радиус 6, 11/700 uppercase +0.08em (`Badge`). Значения (метки, кастом-поля, даты) — `Chip`: тот же силуэт, 12/600 БЕЗ uppercase, потому что текст вводит пользователь.
- **Цвет метки считается, а не назначается** — `web/src/lib/labelChip.ts`: краска выбирается по контрасту из двух, заливка затемняется шагом 0,86 до пяти раз, пока пара не даст 4,5:1. Любой цвет админа остаётся читаемым; парсер обязан переживать `#abc`, `rgb()` и мусор. Покрыто тестом.
- **Треки таблицы задач — из `web/src/lib/taskGrid.ts` и ниоткуда больше.** Шапка колонок и строки берут значения из одной функции; ширина колонки выводится из ТИПА кастом-поля. Контейнер строк скроллится по горизонтали вместе с шапкой (на десяти полях таблица шире рабочей области).
- **Приоритет — планка 3px у левого края, не бейдж**; у `medium` её нет вовсе (87% задач в проде — medium). Выделение строки — амбер-контур всей строки, планкой не красится.
- **Счётчики строки (`comment_count`/`attachment_count`/`blocker_count`) и проекта (`task_count`/`done_count`) заполняет ТОЛЬКО список**, одиночные ручки отдают `null`. Клиент обязан различать `undefined` («не знаем — чип не рисуем») и `0`.
- **Колонку-приёмник на доске считает `BoardView`**, а не `useDroppable` в колонке: карточки — тоже droppable, и `closestCorners` почти всегда отдаёт id карточки, из-за чего подсветка приёма не появлялась.
- **Автовысота textarea — CSS-двойником, не `scrollHeight`**: измерение до загрузки Unbounded давало обрезанный заголовок на 360/390 (`components/ui/AutoGrowTextarea.tsx`).
- **Цвет статуса и приоритета — только из `web/src/lib/tone.ts`** (`STATUS_FILL`/`STATUS_INK`/`PRIORITY_BAR`/`SERIES_COLOR`/`OVERDUE_FILL`): красный — просрочка и ошибка, зелёный — «сделано», ряды графиков — амбер / `--blue-deep` / `--text2`. Дашборд и отчёты — без recharts (`Donut` = `conic-gradient` + `mask` И `-webkit-mask`, `MiniBarChart`, `MeterRow`).
- **Колонки доски и состояние задачи — две независимые оси (0044):** колонка (`project_stages`) — это имя и позиция, состояние — `tasks.done`. Галочка не двигает карточку, перенос между колонками не меняет состояние и не будит наблюдателей (только запись в ленте). Задача без `stage_id` → первая колонка; у проекта ≥1 колонка (удаление последней → 409, удаление колонки с задачами требует `move_to`); `create_project` создаёт 4 стартовые. Контрол состояния — `TaskDoneControl` (круг / зелёная галочка, два состояния), цвета — `DONE_INK`/`DONE_FILL`/`DONE_COLOR` из `lib/tone.ts`. **Имя колонки — чип в строке контекста** (`TaskContextLine.stage`): после схлопывания статусов это единственный признак движения задачи; внутри проекта имена берутся из `useStages`, в кросс-проектных списках — из `TaskResponse.stage_name`. Фронт: `['stages', projectId]` инвалидируется в `onSettled` мутаций задач (иначе «N из M» отстаёт), `useToggleDone` шлёт `{done}` и предлагает undo, бакет «Без колонки» на доске остаётся страховкой для объектов из устаревшего кэша PWA.
- **Создание задачи — `app/services/tasks.py::create_task_record`** (ручка и импорт CSV `POST /projects/{id}/tasks/import?dry_run=`, bucket `task:import` 5/мин; через ручку `create_task` импорт нельзя — там `task:write` 120/мин). Шаблон колонок фиксированный, справочники только существующие, `dry_run` = вся работа + rollback.
- **`Dialog`/`DialogContent` ниже lg — шторка снизу для всех диалогов** (раскладка фиксируется при открытии); **`ResponsiveDialog`** (шторка <lg / модалка 560 ≥lg) — для форм с явным футером, тоже фиксирует раскладку в момент открытия; плавающие слои на мобильном (`MobileViewControlBar`, FAB) — порталом в `body` (`.glass` с `backdrop-filter` — containing block для fixed); `PropertyRows` в скролл-столбце — `shrink-0`; «Новая задача» из сайдбара — `requestInlineCreate` с фолбэком на `CreateTaskDialog`.
- **Карточка задачи (`TaskDetailDrawer`) на десктопе — НЕмодальная панель** (`Root modal={false}`, без Overlay, `onInteractOutside` → preventDefault, авто-фокус на контент, z-40): список под ней виден и кликабелен, клик по строке переключает `?task=`; геометрия — `--shell-gap` (12px, `styles/brand.css`) = отступ панели Shell, `rounded-r-[20px]`; раскладка замораживается при открытии (`desktop` state). На телефоне — модальный лист, кастом-поля — `PropertyRow` (`TaskCustomFields variant="mobile"`, `CustomFieldEditor variant="mobile"`).
- **Секция «ЛИЧНОЕ» на `/my` (0042)** — единственный вход в личное пространство (проекта нет ни в сайдбаре, ни в `/projects`, ни в селекте создания). Стоит НАД вкладками окон дедлайнов и им не подчиняется: личная задача обычно без срока, под «Предстоит» секция была бы пустой; заодно не размонтируется при переключении вкладки (`TaskInlineCreate` коммитит черновик на unmount). Заголовок — типографика `GroupHeader` (13/700 uppercase + mono-счётчик «N · M выполнено»), сворачивается в `useViewConfig` под `PERSONAL_SECTION_KEY`; в свёрнутом виде обязателен «+» — иначе вход в фичу исчезает. Выполненные урезаны до трёх с «Показать все». Строки — `TaskRow compact` по `MY_TASKS_GRID` с ОБЯЗАТЕЛЬНЫМ четвёртым элементом грида (`cells={<span aria-hidden />}`) и `fallback={null}`. Карточка открывается на самой `/my` через `?task=` (`resolvePersonalTaskParam` чистит чужой id), а не уводит на страницу скрытого проекта. Вся условная логика — `lib/personalTasks.ts` + юнит-тесты.
- **Проект на телефоне:** компактная шапка (eyebrow «KEY · N задач · M секций», без описания/кнопок) + чип «Фильтры (N)» → `MobileFilterSheet` (BottomSheet с `TaskFilterBar layout="stack"`); десктопный тулбар `hidden lg:block`; в строках списка контекст без имени секции (`fallback` не передаётся).
- **Сайдбары (решение владельца 2026-08-21):** бренд = марка-маяк `brand/signaris-mark-on-{dark,light}.svg` 26px + «Hub»; роль — `HubRoleChip` у имени в футере (админ амбер, остальные `secondary`); горизонтальный локап «Signaris» остаётся `/p/` и сертификату.
- **«Глазами сотрудника»:** `?preview=1` принимают и `GET /learn/courses/{id}`, и `GET /learn/lessons/{id}` (замки/`next_locked` как у профиля); фронт пробрасывает флаг ТОЛЬКО по ссылкам страницы курса/урока (`LearnCoursePage` → `LessonRow hrefSuffix`, `LearnLessonPage` → `courseHref`/следующий урок).
- **«Управление» — один маршрут `/learn/admin?tab=`**, гейты по сегментам через `adminSegmentsFor(me)` (`learnNav.ts`) — та же логика, что на бэкенде; старые `/learn/admin/<seg>` — редиректы НАВСЕГДА (push шлёт их). Опросы и ассортимент — маршруты `/learn/surveys/:id`, `/learn/products/:id`. `plural()` из `lib/typography.ts` уже содержит число. Сертификат печатается через `[data-cert-print]` + `@page A4 landscape` (лист 1123×794, литеральные цвета бумаги — единственное место в системе). `GET /learn/courses/{id}?preview=1` — курс глазами сотрудника; `preview: bool = False` keyword-only (не `Query`, тесты зовут хендлер напрямую).
- Превью-стенды вне деплоя: `web/preview.html` (обучение) и `web/tracker.html` (трекер, состояние в хеше `#screen=…&mode=…&theme=…&fields=0|10`). Исключены в `deploy.sh`.
