### Наблюдение по правам (прод, 24.08)

У **всех 11 активных профилей прода `content_role = 'none'`** — значит аудитории
настраивают hub-админы (`resolve_content_role` пускает их как `admin`), а
`dry-run` и новые счётчики для не-админа с ролью publisher закрыты гейтом
publisher+. Для аккаунта без прав интерфейс деградирует корректно: список
значений рисуется без «· N сотрудников», красных тостов нет (у обоих хуков
`suppressGlobalError`). Проверено на проде под member-аккаунтом (403 у
`dimension-counts` И у существующего `dry-run` — это не регресс), полный
сценарий со счётчиками проверен на staging.

## Инварианты (продублированы в CLAUDE.md)

- Срок задачи — календарный день display tz: бэкенд `app/services/taskdates.py` (`start_of_today_utc`, `due_noon_utc`, `overdue_clause`), фронт `lib/taskDates.ts` (`dayKey`/`todayKey`/`dueDayToIso`/`isOverdue`); никаких `due_at < now()` и `T12:00:00` в новых местах.
- Состояние задачи — `tasks.done` (0044), фильтр `?done=` через `services/tasks.py::apply_done_filter`; старый `status` отвечает 422 (`reject_legacy_status`).
- Inline-создание: blur/unmount коммитят, Escape отменяет; `lib/inlineDraft.ts` — единственное место логики.
- Гейт теста: `Quiz.is_required` + `services/quiz_gate.py::derive_quiz_state`; `complete_lesson` — три предусловия.
- Текст файла библиотеки — `material_versions.extracted_text` (воркер), индекс берёт его при каждой переиндексации.
- Миграции: 0041 — `material_version_text`, 0042 — личные проекты, 0043 — `media_files.duration_sec`, 0044 — свободные колонки доски и `tasks.done`; следующая (0045) дропает legacy-колонки `tasks.status` и `project_stages.system_status`.
- Счётчики аудитории (`dimension_counts`) тенант не фильтруют — как и `dry_run`: выборку сужает RLS. В интеграционных тестах (суперпользователь, RLS не действует) числа по общим ключам вроде `org_roles` проверяются ДЕЛЬТОЙ, а не абсолютом.
